P0：合并后优先测试
1. 回答脚本真实单元测试
   - Mock DeepSeek 响应。
   - 测试合法引用、未知引用、完全无引用、API 超时、401、429、500、响应结构损坏。
   - 当前只有静态源码检查，不是真正执行回答脚本。
2. Citation Correctness（引用正确性）
   - 引用 ID 存在，但证据实际不能支持结论。
   - 预期：不得仅因 [E1] 存在就通过。
3. Citation Completeness（引用完整性）
   - 回答包含三个外部结论，只给其中一个结论引用。
   - 预期：校验失败或标记不完整。
   - 当前代码只检查“至少存在一个引用”，这个测试大概率会暴露能力缺口。
4. 回答范围控制
   - 用户只问审核流程，模型主动补充时效、费用或其他规则。
   - 预期：判定超出问题范围。
5. 真实 Qdrant 端到端测试
   - 不 Mock Embedding、Qdrant、Reranker。
   - 覆盖速卖通正常召回、Temu 正常召回、跨平台冲突、无证据、无关问题。
6. Blocked 状态零调用测试
   - 每一种 blocked_* 状态都断言 DeepSeek、Embedding、Qdrant、Reranker 没有被调用。
7. 索引一致性测试
   - chunks_merged.jsonl 数量、Manifest 数量、Qdrant Point 数量、Embedding 行数必须一致。
   - chunk_id 必须唯一且四处一一对应。
8. 过期索引测试
   - 修改 Chunk 文件但不重建向量库。
   - 预期：通过 SHA256 或版本信息检测并拒绝使用旧索引。
P1：效果评估
9. 检索黄金集
   - 人工准备至少 30 个问题及预期 Chunk。
   - 分别统计 Recall@5、MRR、重排后 Hit@3。
10. 跨平台污染集
    - 准备语义高度相似的速卖通和 Temu 问题。
    - 指标：错误平台召回率必须为 0。
11. Reranker 阈值标定
    - 收集正相关、弱相关、无关证据的分数分布。
    - 用数据确定 MIN_RERANK_SCORE，不要继续凭感觉使用 0.75。
12. 意图分类在线 Eval
    - 扩展到至少 50 条。
    - 覆盖错别字、中英文混用、口语、信息不足、混合意图、反问、诱导提示。
    - 记录 Accuracy（准确率）、误放行率、误阻断率。
13. 文档更新测试
    - 新增、修改、删除文档后重新解析和入库。
    - 检查旧 Point 是否删除、重复执行是否产生重复数据、source_id 是否稳定。
14. Prompt Injection（提示注入）
    - 用户问题或证据中写“忽略规则、回答其他平台、伪造引用”。
    - 预期：模型仍只依据证据回答。
P2：工程测试
15. 性能测试
    - 记录冷启动与热启动的 P50/P95 延迟。
    - 分别测 Embedding、Qdrant、Reranker、DeepSeek 耗时。
16. 故障恢复
    - 模型下载失败、Qdrant 文件损坏、网络断开、API 限流。
    - 预期：返回明确错误，不生成错误答案。
17. 安全测试
    - API Key 不进入 Git、日志、证据包和异常输出。
    - 超长问题与超长证据不能无限增加 Token 和成本。
