# P0-CONC-MIN：Embedded Qdrant 并发边界

本次探针使用现有 `output/qdrant_storage` 与 collection
`rag_rules_bge_small_zh_v1_5`，仅执行 `get_collection` 和
`count(exact=True)`。每个客户端均在 `finally` 中关闭；并发场景超时为 5 秒。

## 实测结果

| 场景 | 结果 | 场景耗时 | 异常类型 |
|---|---|---:|---|
| 两次顺序打开、读取、关闭 | 成功（2/2） | 22.128 ms | 无 |
| 两个线程同时各自创建客户端并读取 | 失败（1/2） | 27.515 ms | `RuntimeError`（1 次） |
| 两个进程同时各自创建客户端并读取 | 失败（1/2） | 1094.458 ms | `RuntimeError`（1 次） |

两个并发失败均为同一类存储占用错误：同一 Embedded Qdrant 存储已被另一
Qdrant client 实例访问。顺序基线成功，因此本次探针执行有效。未加载 Embedding /
Reranker，未调用 DeepSeek，未重跑既有 193 项测试。
退出判定：顺序基线成功，探针退出码为 0；线程/进程并发失败不影响退出码。

## 最终支持边界

已确认支持同一进程内的顺序打开、只读、关闭。当前每请求新建客户端的实现不支持
重叠请求；多进程/多 Worker 不可用；共享单客户端的线程并发未测试。线程场景与
进程场景均是多个客户端同时打开同一路径，失败属于有效边界观测。需并发访问时应
使用独立 Qdrant 服务；该结论仅覆盖本探针使用的只读操作。
